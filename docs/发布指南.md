# 发布指南 / Release Guide

以 `comfyui-x-wide-image-sender-receiver` 为例，记录一次完整发布（GitHub 仓库 + Comfy Registry）。

## 0. 发布前自检

- [ ] `pyproject.toml`、`__init__.py`（`__version__`）、`CHANGELOG.md` 三处版本号一致；
- [ ] `README.md` / `README.en.md` 顶部互链，`LICENSE`、`NOTICE`、`CHANGELOG.md` 都在；
- [ ] `python -m py_compile nodes.py __init__.py` 通过；
- [ ] 前端 JS 语法检查通过（例如 `node --check`，把文件复制成 `.mjs` 再检查）；
- [ ] 重启 ComfyUI 后，节点出现在 `X-WIDE/Image` 分类下，右键菜单里有「信息 / About」；
- [ ] README 里引用的截图都存在（本仓库用 `docs/images/`）。

## 1. 创建 GitHub 仓库

1. 打开 <https://github.com/new>；
2. **「Repository name」栏必须填 `comfyui-x-wide-image-sender-receiver`**
   （曾经把名字填成账号名 X-WIDE，导致所有链接 404）；
3. 不要勾选自动创建 README / .gitignore（本地已经写好了）；
4. 创建后拿到地址：`https://github.com/XWIDE/comfyui-x-wide-image-sender-receiver`。

## 2. 推送本地代码

在本包目录（`ComfyUI/custom_nodes/comfyui-x-wide-image-sender-receiver`）
里执行（目录名以本机实际情况为准，仓库名与目录名不一致不影响运行）：

```bash
git init
git add .
git commit -m "feat: X-WIDE Image Latent Sender / Receiver 1.0.0"
git branch -M main
git remote add origin https://github.com/XWIDE/comfyui-x-wide-image-sender-receiver.git
git push -u origin main
```

- 首次 push 会弹出「Connect to GitHub」，选 **Sign in with your browser** 完成授权；
- 如果报证书错误，可执行 `git config --global http.sslBackend openssl` 后重试；
- 推送完成后确认 `pyproject.toml` 里的 `[project.urls]` 都与真实仓库地址一致。

## 3. 别人怎么安装

- **ComfyUI Manager** → Install via Git URL → 填仓库地址；
- 或手动 `git clone` 到 `ComfyUI/custom_nodes/` 后重启；
- 页面要 **Ctrl + F5 硬刷新**，否则可能读到旧的前端缓存。

## 4. 上架 Comfy Registry（让 ComfyUI Manager 能搜到）

只有上架 Registry 之后，Manager 里才能搜到、才有缩略图（只 push GitHub 不会进 Manager）。

**方式 A：GitHub Actions 自动发布（本仓库已配置，推荐）**

`.github/workflows/publish_action.yml` 已经放好，触发条件是「push 到 `main` 且改了 `pyproject.toml`」，
也可以在 Actions 页面手动跑。第一次用需要先在网页上填两样东西：

1. 去 <https://registry.comfy.org> 登录 → 头像 / 设置里 **API Keys** → 新建一个 publishing key，复制它；
2. 去 <https://github.com/XWIDE/comfyui-x-wide-image-sender-receiver/settings/secrets/actions>
   → **New repository secret**：
   - **Name**：`REGISTRY_ACCESS_TOKEN`
   - **Secret**：粘贴上一步的 key
   → **Add secret**；
3. 去 <https://github.com/XWIDE/comfyui-x-wide-image-sender-receiver/actions/workflows/publish_action.yml>
   → **Run workflow**（分支选 `main`）→ 等它变绿；
4. 验证：打开 <https://api.comfy.org/nodes/x-wide-image-sender-receiver>，
   返回 200 且 `"status":"NodeStatusActive"` 就是上架成功（没上架时是 404 `Node not found`）。

**方式 B：本地 comfy-cli 手动发布（没配 Actions 时用）**

```bash
pip install comfy-cli
comfy node login          # 浏览器登录，Publisher 选 xwide
# 在本包目录执行
comfy node publish
```

要点：

- 每次发布**版本号必须递增**（`pyproject.toml` 的 `version`），否则会被拒绝；
- `PublisherId` 必须与登录的发布者一致（本包为 `xwide`），不一致时按提示修改；
- 若这个 PublisherId 已被占用，换一个并同步修改 `[tool.comfy] PublisherId`；
- `.comfyignore` 里排除了 `docs/`、`.github/`、`__pycache__/`，所以 README 里的图片 / 链接
  必须写**绝对地址**（本仓库已经全部改成 `raw.githubusercontent.com` / `blob/main`）；
- **必须先 push 到 GitHub，Registry 才能抓到 Icon 图片**，再执行发布。

## 5. 关于节点缩略图

- **ComfyUI Manager 里显示的节点缩略图来自 Registry，而不是仓库里的图片**；
- 因此 `[tool.comfy] Icon` 必须写**完整 URL**，本包用的是：
  `https://raw.githubusercontent.com/XWIDE/comfyui-x-wide-image-sender-receiver/main/web/logo_xwide_icon.png`
- 图片要先 push 到 `main` 分支，Registry 才能抓到。

## 6. 发布后续

- 功能变化 / BUG 修复都要写进 `CHANGELOG.md`，并同步递增版本号；
- 修改了原项目代码的话，`NOTICE` 里的修改清单也要一并更新（GPL-3.0 义务）。

## 7. 迭代版本（打标签 + 发 Release）

发布新版本时，除了 push 代码，**还要打标签并在 GitHub 上发一个 Release**，
这样「Releases / 迭代版本」页面里才会显示这个版本（别人也能按版本下载 ZIP）：

```bash
git add -A
git commit -m "feat: Latent Sender / Latent Receiver（v1.1.0）"
git push origin main
git tag -a v1.1.0 -m "X-WIDE Image Latent Sender & Receiver v1.1.0"
git push origin v1.1.0
```

然后在 <https://github.com/XWIDE/comfyui-x-wide-image-sender-receiver/releases/new> ：

1. **Choose a tag**：选刚推上去的 `v1.1.0`（或是现打新的）；
2. **Release title**：`v1.1.0 — 新增潜空间收发 / Latent Sender & Receiver`；
3. **Describe this release**：把 `CHANGELOG.md` 里对应版本的内容粘进去
   （现成的文案见 `docs/RELEASE_NOTES_v1.1.0.md`）；
4. 需要上传打包 ZIP 的话，用 `git archive` 生成：
   `git archive --format=zip --prefix=comfyui-x-wide-image-sender-receiver/ -o x-wide-v1.1.0.zip v1.1.0`
   （GitHub 也会自动提供 Source code 压缩包，通常不用手动传）；
5. 点 **Publish release**。

Comfy Registry 那边也要同步：只要 `pyproject.toml` 的 `version` 变了并 push 到 `main`，
`publish_action.yml` 会自动发布（也可以在 Actions 页面手动 `Run workflow`），
否则 Manager 里看到的还是旧版本。
